# 风格：选、用、改、做自己的

同一个模板、同一份文案，换一个风格就是另一部片子：风格决定**材质、色彩、字体、运动质感、转场、声音、招牌动作**，
不决定结构和内容。每个风格是 `styles/<slug>/` 下的四个文件：

| 文件 | 内容 |
|---|---|
| `STYLE.md` | 风格规格，11 节固定结构（本质与不是什么 → 材质 → 色彩 → 字体字幕 → 运动 → 镜头 → 声音 → 招牌动作 → 常见坑 → 引擎 → 变化空间）。**做片前读完所选风格的 STYLE.md** |
| `theme.css` | 主题变量和共享组件的改写（只加载一个，写在 `:root`） |
| `style.js` | 运动钩子 `K.defineStyle({...})` |
| `style.json` | 名称、一句话、适合内容、默认声音调色板、支持的片型 |

## 风格一览

| slug | 名称 | 一句话 | 声音 | 适合 |
|---|---|---|---|---|
| `nebula` | 星云玻璃 | 深蓝紫星空、玻璃卡片、逐字从模糊浮现、粒子爆出 logo | synth | AI / 平台类发布、能力总览、"汇成一个入口" |
| `keynote` | 暗场发布会 | 近黑舞台、发丝网格、唯一一个强调色、卡拍落位、光扫揭幕 | mallet | 软件版本发布、单一功能、大数字 |
| `swiss` | 瑞士网格 | 纸面、12 栏网格、左对齐、一个信号红、槽口上升和刀切 | motorik | 品牌系统、流程与规则、B2B 理性说服 |
| `blueprint` | 蓝图工程 | 蓝图纸、白色线稿、构造线和尺寸标注、绘图仪逐笔画出 | ambient | 架构、原理、"它是怎么构成的" |
| `whiteboard` | 白板手绘 | 白板、手写标题、微抖的框、红马克笔圈重点、板擦转场 | felt | 讲解、培训、方法论、三步上手 |
| `terminal` | 终端荧光 | 黑底荧光绿、等宽字、块光标打字、扫描线、CRT 关机 | chip | 开发者工具、命令行、自动化、"一行搞定" |
| `editorial` | 杂志纸本 | 奶油纸、衬线标题、宽留白、陶土色、从容的淡入 | felt | 理念、案例故事、年度回顾、高端 B2B |
| `pop` | 波普活力 | 黄色半调、粗黑描边硬投影、弹跳入场、描边彩纸 | pop | 大众消费、活动推广、轻量工具、年轻用户 |

用户自己的风格在 `$PROMO_STYLES`（默认 `~/.promo-styles/<slug>/`），索引是那里的 `README.md`；同名时用户的优先。

## 怎么选

1. **先看内容和受众，再看喜好。** 用上表"适合"一栏给出两三个候选，各一句理由；严肃主题（合规、医疗、金融）不推荐 pop，
   面向开发者优先 terminal / keynote，讲方法优先 whiteboard / blueprint。`nebula` 是 `init` 的默认值，也是最像"生成默认"的外观
   （深色虚空、玻璃卡片、粒子，见 craft.md「默认值黑名单」）：只在内容真的需要它时选，不要因为它是默认就用。
2. **用用户自己的内容比较**，不要用模板占位文字：先把 2–3 个关键场景写成真实文案，再出风格对照图：

   ```bash
   node <skill>/scripts/init.mjs --dir .promo/film --cut motion --all-styles       # 拷入全部风格
   node <skill>/scripts/styleboard.mjs --film film.html --timeline timeline.json --at 3,9,24 --styles keynote,swiss,editorial
   ```

   每行一个风格、每列一个时刻，读图后给用户看，让用户选或说"都不对"。
3. **定了之后出三张风格帧**（`render.mjs --preview`，用真实画面代码，不是示意图）：开场、一个内容场景、招牌动作那一刻；
   对照所选 `STYLE.md` 自查一遍再往下做。
4. 风格写进 `timeline.json` / `script.json` 的 `"style"`（`init.mjs --style` 会写），声音调色板写进 `cues.json` 的 `"palette"`。
   临时换风格看效果：`render.mjs --style pop --preview 3,9`，不改文件。

**一部片子一个风格。** 不在片中途换风格；想要对比（旧 / 新）用同一风格里的色彩和材质对比来做。

## 品牌层：品牌规范优先于风格

项目有自己的品牌规范（色值、字体、圆角、logo）时，风格只提供动作和版式语法，品牌的值由 `brand.css` 覆盖：

```bash
node <skill>/scripts/init.mjs --dir .promo/film --cut narrated --style swiss --brand   # 拷入 brand.css，timeline/script 写 "brand": "brand.css"
```

- `brand.css` 在风格的 `theme.css` 之后加载，只写品牌规定的那几个变量（`--accent`、`--c1…`、`--font`、`--head`、`--radius`……），其余留给风格。
- 值从品牌自己的规范或设计文件里抄，不凭印象取色；一个值找不到出处就不写，让风格的值留着。
- 品牌色对这个风格的底色太深或太浅时，只当强调色（填充、线、标记），不当正文字色；`check.mjs` 会量对比度。
- logo 用品牌给的 SVG 替换模板的 `<symbol id="mark">`，不重画、不改色、不加特效。
- 品牌规范、logo 文件和色值只放在这个项目的片子目录里，不写回本 skill 或用户的通用风格（SKILL.md 硬规则 10）。

## 风格接口（写模板或做新风格时看）

模板只调用下面这些，**不写死颜色、字体和入场方式**——这样换风格才不用改模板。

| 调用 | 风格钩子 | 做什么 | kit 默认 |
|---|---|---|---|
| `K.text(el, l, at, { st, outAt, outD })` | `text` | `[data-split]` 元素逐字入场 / 离场（`el._chars` 是每个字的 span） | 逐字从模糊上浮 |
| `K.item(el, l, at, { d, dy, scale, blur, outAt, outD })` | `item` | 一整个元素（卡片、胶囊、行）入场 / 离场 | 淡入上移 |
| `K.mask(el, l, at, d)` | `mask` | `.m` 遮罩里的一行从下方升起 | 遮罩上升 |
| `K.lockup(el, l, at)` | `lockup` | logo 标记 + 名字落定（模板先设好整体 opacity） | 1.12→1 缩放 + 去模糊 |
| `K.hit(t, T, cx, cy)` | `hit(ctx, t, T, cx, cy)` | 招牌动作，画在 `canvas#fx`，T 为峰值时刻 | 粒子收拢爆发 |
| （自动） | `bg(ctx, t, W, H)` | 每帧画 `canvas#bg` 全屏背景 | 无 |
| 场景 `fadeIn` / `fadeOut` | `scene(el, p, phase)` | 场景转场；只用 opacity / clip-path / filter，不用 transform | 淡入淡出 |
| `K.drawLinks(svg, l)` | `draw`、`sparks` | 连线描出的缓动；`sparks: false` 关掉流动光点 | `out5`，有光点 |

钩子必须是时间的纯函数：不用 `Math.random`、不靠调用顺序和计数器；需要"随机"的倾角、抖动用
`K.hash(文字或位置, seed)`。元素停稳后把 `transform` / `clipPath` 清空（`check.mjs` 把带裁切的字当成还没读完）。

**主题变量**（`kit.css` 有默认值，主题只改需要的）：

- 表面与文字：`--bg --ink --sub --dim --line --card --card-line --card-shadow --radius --track --knob`
- 角色色：`--accent --accent-ink --good --warn --bad`，类别色 `--c1 … --c6`
- 强调词：`--warm --cool`（`.g.warm` / `.g.cool`；纯色写成两段相同颜色的渐变）
- 字体：`--font --head --head-weight --head-track --mono`
- 可选：`--hit-label`（blueprint 尺寸标注文字，默认不画）

**共享组件**（主题可改写）：`.stage .card .bar3 .chap .ctitle .cap .caret .hub .orb .ringline .lock .pill .btn .ghost .dot .foot .sub .curtain .gradtext .shot`，
logo 标记的部件 `.mk-glow .mk-body .mk-line .mk-dot`。SVG 里的颜色写成 `style="stop-color:var(--c2)"` 或 `fill:var(--accent)` 才会随主题变。

**字体**：只用系统字体，或把 OFL 等允许嵌入视频的字体文件放进片子的 `fonts/` 用 `@font-face` 引用；渲染时不联网取字体。
中文片要确认字体有中文字形，没有就在字体栈里给中文回落。

## 改一个风格，或做自己的风格

用户说"想改改这个风格""做成我们自己的风格""从零做一个风格"时按这一节走。一次只问一个问题（用 AskQuestion，2–3 个选项，
推荐项放第一个并写理由，最后一项"自由讨论"）；能查到的（STYLE.md、用户文件）不问；总共不超过十个问题，用户说"你定"就按推荐走。

### 1. 从哪里起步

- **改一个现成风格**：用户点名一个；没点名就按上面"怎么选"给两三个候选。只认一个底子；想混两个，以"本质"最接近的为底，
  另一个只借具体动作。
- **从空白开始**：用户用自己的话描述，或给一张图 / 一段视频。选一个最接近的现成风格当**技术底子**（材质和引擎最近的），
  最多再借两个风格的动作。第一个问题就是这个选择。

无论哪种，先读完底子的 `STYLE.md` 再提第一个问题。

### 2. 一起定下来

先问用途：做什么片子、给谁看、发在哪（竖屏信息流要 1080×1920，`--size 1080x1920`）、品牌色 / logo / 字体。
然后把可改的地方分三组讲给用户：

| 组 | STYLE.md 章节 | 怎么跟用户说 |
|---|---|---|
| **放心改** | 3 色彩（在原有逻辑内换色）、4 字体、5 运动（快慢、动多少）、7 声音调色板、8 招牌动作（换或加一个） | 风格还是它自己；每项给 2–3 个具体方向 |
| **会改变性格** | 2 材质与渲染、3 色彩逻辑本身、6 镜头语法 | 可以，但说清楚会失去什么 |
| **不能改** | 1 本质（以及"它不是什么"）、10 引擎 | 那就是另一个风格了；建议换一个更近的底子 |

把模糊的愿望翻译成选项（给用户选，不要自己悄悄改）：

| 用户说 | 通常意味着 |
|---|---|
| 高级一点 | 更少的颜色、更强的明暗对比、更慢的运动、更多留白、更细的字重 |
| 年轻、活泼 | 更亮的强调色、卡拍切换、更有弹性的缓动、更多打击乐 |
| 安静、沉稳 | 更慢的节奏、更长的停留、更少的运动元素、更稀疏的配器 |
| 像我们品牌 | 品牌色当强调色而不是底色；品牌字体用于标题；logo 在开头和结尾 |

- **品牌**：保持底子的明暗结构让字可读，品牌色先作为 `--accent` 进来。品牌字体必须有中文字形、允许用于视频；logo 和字体由用户提供。
- **一起变的东西**：动得更快就要声音更密；底色更暗就要复查文字对比度；换了材质就把新材质的坑写进第 9 节。
- **招牌动作最多换一个**，它是风格被认出来的地方。
- **每轮最多五处改动**，多了没法判断；因片子语言被迫的改动（中文字体）不算。
- **不需要新风格的情况**：只想换结构、开场、结尾、节奏、配音——这些每部片子本来就自由（第 11 节"变化空间"），直接做片即可。

问完给用户一份简短总结：每项决定、改前 → 改后、代价。**等用户确认**再动手。

### 3. 写下来、做出来

```bash
node <skill>/scripts/init.mjs --new-style night-lab --name 夜间实验室 --from keynote   # 或不写 --from，从空白模板起步
```

它把底子（或 `styles/_template/`）拷到 `~/.promo-styles/night-lab/`，替换 slug 和名称，并更新 `~/.promo-styles/README.md` 索引。
然后依次改：`theme.css`（变量和组件）→ `style.js`（钩子）→ `STYLE.md`（把改动写进对应章节，读起来是一份完整规格，
不留"见底子"的空洞；标题下一行写"基于 <底子名>（<slug>）"）→ `style.json`（一句话、适合、声音）。
另写一份 `CHANGES.md`：每项改动一行（章节 | 原来 | 现在 | 为什么）。

**证明它**：

1. **风格帧**：在一个测试片目录里 `init.mjs --cut motion --style <底子> --all-styles`，用
   `styleboard.mjs --styles <底子>,<新风格> --at …` 出同一帧的左右对照（底子在上、新的在下，只有改动不同）。给用户看并等反馈；
   两轮还不对就建议换更近的底子。
2. **演示片**（15–30 s）：主题用用户的；`CHANGES.md` 每一行都要在画面里清楚出现一次，招牌动作出现一次；
   只要音乐和音效；同样过 `check.mjs`、`review.mjs` 和 `verify`。成片和海报存成风格目录里的 `test.mp4`、`test.jpg`。

### 4. 留下来

用户确认后它就是用户的风格：以后说"用我的 <名称> 风格做一个……"，`init.mjs --style <slug>` 就会从 `~/.promo-styles/` 找到它。
用户还想改：只改用户说的地方，同步 `STYLE.md` 和 `CHANGES.md`，重出风格帧和演示片。
本 skill 更新后，如果底子的 `STYLE.md` 有修复，提一次、问用户要不要带进他的版本，不擅自改。

自己的风格**永远不写回本 skill 的 `styles/`**；里面也不放客户数据、录屏和保密素材（见 SKILL.md 硬规则 10）。
