# 审片：机检、审片图、修改清单

两道检查，先机器后人。量得出来的（读不读得完、字够不够大、有没有空屏、对比度）交给 `check.mjs`；
量不出来的（看不看得懂、好不好看）靠 `review.mjs` 的图和一段"陌生人式"的描述。两道都在全量渲染之前做，
改一轮、复查一轮，再渲染。

```bash
node <skill>/scripts/check.mjs  --film film.html --timeline timeline.json [--pace calm] --json check.json
node <skill>/scripts/review.mjs --film film.html --timeline timeline.json --check check.json
```

## check.mjs 的警告

逐 0.1 s 采样整部片子，按第一次看的观众的视角报告；每条都带时间、文字和改法。默认只报告不拦截，`--strict` 有警告即失败。

| 代码 | 意思 | 阈值 | 常见改法 |
|---|---|---|---|
| `line_unread` | 字没读完就走了 | 需要 0.5 s + 每词 0.3 s（中文按**词**切分，不按字）；promo 低于 75% 报，calm 低于 100% 报；一两个词可以只闪 0.4 s；全片最后一句 ≥ 2 s（calm 3 s） | 提前入场、晚点离场、删字 |
| `sub_short` | 字幕太短 | < 1.2 s（calm 1.8 s） | 并进下一句，或让旁白多说半句 |
| `text_below_floor` | 要读的字太小 | 小于画面短边的 2.6%（1080 → 28 px）超过 0.5 s | 放大；纯装饰（窗口标题栏、行号、坐标刻度、重复的章节角标、图标）标 `data-noread` |
| `first_frame_empty` | 封面是空的 | 第 0 帧只有背景，或被幕布盖住 | 开场第一句或主视觉在 0 s 已经在画面上，不从黑场淡入 |
| `empty_stretch` | 空屏 | 画面上没有可读内容超过 0.75 s | 下一个入场在上一个离场结束前开始（重叠 30–50%），或让一个物体跨过切点 |
| `dead_stretch` | 画面死了 | 超过 3 s 完全不变（calm 4.5 s，旁白在撑着；最后 3 s 的片尾不算） | 加一拍：揭示、数字、界面反应；有意的停留标 `data-hold` |
| `idle_drift` | 到位后还在漂 | 落定的元素还在慢慢浮动 / 呼吸 / 慢推 ≥ 2.5 s | 到位就停；镜头要动就带着目的动（从全景推到要看的那块） |
| `outside_safe` | 出了安全框 | 字超出 90% 动作安全框（1080p：左右 96 px、上下 54 px）超过 0.5 s | 往里收；关键字放进 80% 标题安全框 |
| `clipped_text` | 字被裁 | 被 overflow 容器或画框裁掉超过 0.5 s | 加宽、缩短、允许换行 |
| `low_contrast` | 看不清 | 在节拍帧实测字色与背后像素的对比：< 4.5:1（≥ 36 px，或 ≥ 28 px 且粗体：< 3:1） | 要读的字用 `--ink` / `--sub`，不用 `--dim`；浅底上的彩色字换深一档；或加底板 |
| `film_silent` | 没声音 | 15 s 以上的片子没有声音文件 | 写 `cues.json` 跑 `music.mjs`，或 `--audio` 指定 |
| `text_overlap` | 字压字 | 两段要读的字（不透明度 > 0.5）互相重叠 ≥ 0.2 s（宽度重叠 > 4 px，高度重叠超过较矮那段的 30%） | 错开位置或时间；字幕和 `.foot` 共用底部一条带，别的字不放进去 |
| `media_missing` | 图没加载出来 | 图片解码失败或 `K.setSrc` 报错 | 检查路径和帧数（`data.footage` 的 `count`） |
| `media_soft` | 推近过头发虚 | 图片显示尺寸超过原始分辨率 1.15 倍、持续 ≥ 0.5 s | 用 `deviceScaleFactor: 2` 重截，或少推一点 |
| `shot_treated` | 录屏被调了色 | `.shot` / `[data-real]` 里的图片或它的上层有 filter / mix-blend-mode | 风格只改窗口外框，真实画面保持原色 |
| `not_deterministic` | 同一时刻渲出两样 | 倒序重渲 12 个探测帧，和正序的结果不一致 | 找依赖上一帧的状态、没种子的随机、`Date.now()`；每帧把用到的属性重新赋值 |

两个标记：`data-noread`（这段字不需要读：跳过阅读、字号、对比检查）和 `data-hold`（这里是有意的停留：
跳过静止检查）。它们是给装饰和真正的停顿用的，不是给问题消音的；每用一次都在 REVIEW.md「保留下来的警告」里写一句理由。

几条经验：

- 字号警告最多的地方通常是"假界面"：真实产品界面字很小，放进 1080p 视频要么推近 1.6–2× 让字到 26–28 px 以上，要么只留观众要读的那一行。
- 对比度在深色风格里多半出在 `--dim`，在浅色风格里多半出在彩色字（绿色"完成"、橙色"警告"）：彩色作填充没问题，作文字要换深一档。
- 空屏几乎都出在切点：上一场全部淡出、下一场才开始搭建。招牌时刻前的停顿 0.3–0.75 s 是好的，再长就是空。
- 模板里占位的录屏场景在没有放录屏帧时会报 `dead_stretch`，这是对的：放进真实录屏后它会动起来。

## review.mjs 的审片图

写到 `review/`（每次重画，旧图删掉）：

- `beats-*.jpg`：每个场景刚开始、中间、招牌时刻之后各一格，左上角标场景和时间。
- `cuts-*.jpg`：每个切点一行，−0.2 / −0.1 / 0 / +0.1 / +0.2 s。
- `phone-*.jpg`：同样的节拍帧缩到 360 px 宽，就是手机上看到的大小。
- `REVIEW.md`：审片记录模板（已存在就不覆盖），`--check` 会把机检警告列进去逐条处理。

怎么看：

1. **先只看 beats 图，不看脚本**。逐格写下一个陌生人会怎么描述它（"深色背景上一个窗口，里面一行字在打"），
   再对照这一拍本来要讲的事。描述讲不出要讲的事，就是问题；只看图讲不通故事，加旁白也救不回来。
2. **cuts 图**：运动有没有带过切点、方向是否一致（从右边出去的，下一场从左边进来）、有没有一格空白或闪一下。
3. **phone 图**：360 px 宽下要读的字还能不能读、主体是否至少占画面高度的三分之一。
4. **连着三格同一种构图**（居中大字、三卡并排、标题压在暗化截图上）就是单调，换一格的景别或版式。

## 修改清单

每条一行：`t=4.2s · 位置 · 问题 → 改法 · 保留什么`。按严重程度排：

- **P0**：看不懂、读不完、出错、违规（数字不对、免责声明看不清、地图不合规）——必须改。
- **P1**：明显削弱效果（空屏、死画面、切点断掉、焦点不清）——应该改。
- **P2**：打磨——有余力再改。

只改一轮：改完重跑 `check` 和 `review`，确认 P0 清零、P1 不新增，再全量渲染。不要给片子打分；
"8/10" 对修改没有帮助，一条具体的 `t=… → 改法` 有。

## 交付说明里照实写

- 做了哪些创作决定（世界、手法、风格、声音调色板）和理由；没做的另外两条故事线。
- 哪些是测量过的（时长、响度、true peak、机检），哪些只看过图；**声音只做了测量，没有人耳试听**。
- 最弱的一个镜头和原因；保留下来的警告和理由。
